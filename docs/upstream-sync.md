- Waveshare board profile, pin assignments, display, ES8311/ES7210 audio,
  microSD, physical controls and optional battery sensing.
- Windows build/flash helpers, firmware packaging, portable board/audio tests
  and a GitHub Actions host-test workflow.
- [Board build and setup guide](../hardware/lantern-firmware/WAVESHARE.md).

The imported firmware keeps upstream's API URL,
`https://quipus-sales-rep-assistant.vercel.app`, in
`hardware/lantern-firmware/main/lantern_board.h` (`LANTERN_API_BASE_URL`).
Copying this repository does not deploy another backend or migrate accounts,
pairing records, recordings, database contents, service credentials or domains.
Use a pairing code generated by the dashboard served by that backend. A future
independent deployment needs its own configuration and a matching firmware API
URL before testing account pairing.

## iPhone setup

Start in the web dashboard's Devices page on the iPhone and create a pairing
code. Join the recorder's `Quipus-XXXX` Wi-Fi network (password `lanternsetup`),
stay connected when iOS reports no internet, return to the dashboard tab and
choose **Open recorder setup**. Firmware 0.9.2 fills the code from the link's
fragment and immediately removes the fragment from the browser address. The
code is not sent as an HTTP query or included in cloud connectivity checks.

Enter the details of an internet-connected 2.4 GHz Wi-Fi network and save. The
recorder restarts; reconnect the iPhone to normal Wi-Fi or mobile data. Setup
checks the existing Quipus website for up to two minutes and returns to its
Devices page when reachable. **Return to Quipus** also works as a manual link.
The dashboard confirms the device's actual account connection; saving settings
alone does not certify pairing or upload success. If an older firmware is
installed, enter the dashboard code manually at `http://192.168.4.1/`.

The local address belongs to the recorder and is still used for the initial
credential transfer. It cannot be replaced with a cloud redirect before setup:
the recorder needs the local Wi-Fi settings to contact that cloud service.
The website does not submit a Wi-Fi password through the internet.

Bluetooth is disabled in this firmware. Safari and Chrome on iPhone do not
provide native Web Bluetooth access; adding a website to the Home Screen does
not supply that missing browser API. Third-party Bluetooth browsers or Safari
extensions require an additional installation and compatibility testing.
The recorder uses Wi-Fi for cloud uploads; the iPhone dashboard accesses those
uploads through the backend.

Browser references:
- [Web Bluetooth implementation status](https://github.com/whatwg/bluetooth/blob/main/implementation-status.md)
- [Chrome Web Bluetooth documentation](https://developer.chrome.com/docs/capabilities/bluetooth)

## Syncing with the co-founder's repository

Configure the remotes once:

```sh
git remote -v
git remote add upstream https://github.com/NathanHor22/Quipus.git
```

If `upstream` already exists, use `git remote set-url upstream` with that URL.
`origin` should point to `https://github.com/jinchuntan/quipus.git`.
To prepare a later sync without changing the shared default branch directly:

```sh
git switch main
git pull --ff-only origin main
git fetch upstream
git switch -c sync/nathan-next
git merge upstream/main
# Resolve any conflicts, run the relevant checks, then:
git push -u origin sync/nathan-next
```

Open a pull request in `jinchuntan/quipus` and review the changes together.
Do not use a force push or a mirror push to synchronize these independent repos.

## Validation of the Waveshare addition

The Waveshare, original and V2 ESP-IDF profiles built successfully in the local
development environment. Portable board/PCM, network setup, USB framing and
encrypted archive tests passed, as did the 290 application tests and TypeScript
checking. These are build/software checks; the Waveshare firmware still needs
on-device validation of display, audio, microSD and power behavior.

The one-time import job also checks the complete resulting Git tree against the
locally prepared tree, reruns board/PCM and Wi-Fi parser tests, and runs the
application tests and TypeScript checking before publishing the import commit.
